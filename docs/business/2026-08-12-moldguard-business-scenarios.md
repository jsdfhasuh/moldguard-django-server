# MoldGuard 模具保养智能体业务场景说明

- **版本**：V2.1
- **日期**：2026-08-13
- **知识库基线**：MOLDGUARD-KB-1.2

## 1. 主场景

```text
自动扫描
→ 自动建立待派工工单
→ 选择保养人员
→ 邮件下发点检知识和报工链接
→ 人员点击链接上报完成情况
→ 正常完成或异常闭环
→ 周期复位和统计
```

## 2. 触发场景

- 注塑 `<1000T`：50,000 有效模次；
- 注塑 `>=1000T`：30,000 有效模次；
- 注塑：从最近有效保养或首次生产起 2 个月；
- 钣金成型类：150,000 有效模次；
- 钣金冲孔落料、连续、边板：400,000 有效模次；
- LC109 必须显式提供连续模或边板类别。

达到条件后自动建立 `PENDING_ASSIGNMENT` 工单。

## 3. 邮件派工场景

平台获取Django返回的：

```text
assignee_email
report_url
knowledge_snapshot_version
```

再从知识库检索本次适用点检知识，发送含“提交报工情况”按钮的邮件。

## 4. 正常报工

人员在网页表单填写点检结果、完成说明和实际工时。全部必检项完整且无未处理异常时，Django直接将工单设为 `COMPLETED`，并按工单类型复位周期。

## 5. 异常报工

存在不合格或无法处置的问题时进入 `ABNORMAL_REPORTED`：

```text
继续处理 → IN_PROGRESS → 重新点检和报工
或
创建关联修模任务 → REPAIR_LINKED → 修模完成 → IN_PROGRESS
```

异常工单不结单、不复位。

## 6. 比赛演示

1. 扫描并自动建单；
2. 选择候选人员；
3. 发送含点检知识和报工链接的邮件；
4. 点击链接提交正常报工；
5. 展示工单完成、周期复位和工时；
6. 快速展示异常报工与关联修模分支。
