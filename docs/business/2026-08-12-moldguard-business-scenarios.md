# MoldGuard 模具保养智能体业务场景说明

- **版本**：V2.2
- **日期**：2026-08-13
- **知识库基线**：MOLDGUARD-KB-1.2

## 1. 主场景

```text
自动扫描
→ 自动建立待派工工单
→ 选择保养人员
→ 邮件下发点检知识和报工链接
→ 人员点击链接上传完成说明和现场图片
→ 平台结合锁定知识与图片给出AI建议
→ Django正常完成、异常闭环或要求补充材料
→ 周期复位和统计
```

## 2. 触发场景

- 注塑 `<1000T`：50,000 有效模次；
- 注塑 `>=1000T`：30,000 有效模次；
- 注塑：从最近有效保养或首次生产起 2 个月；
- 钣金成型类：150,000 有效模次；
- 钣金冲孔落料、连续、边板：400,000 有效模次；
- LC109 必须显式提供连续模或边板类别。

达到条件后自动建立 `PENDING_ASSIGNMENT` 工单。

## 3. 邮件派工场景

平台获取 Django 返回的：

```text
assignee_email
report_url
knowledge_snapshot_version
```

平台从知识库检索本次适用点检知识并回写工单知识包；Django 随后向被派工人发送含“提交报工情况”按钮的邮件。

## 4. 员工报工与 AI 审核

人员只在 Django 网页填写完成说明、实际工时并上传现场图片。Django 保存材料后 Webhook 唤醒平台；平台读取文字、全部图片和锁定知识包，返回 `COMPLETE`、`ABNORMAL` 或 `NEEDS_MORE_INFO` 建议。

平台没有员工报工页面。未验证视觉输入时只能返回 `NEEDS_MORE_INFO`，工单保持原状态，人员需从原链接提交新材料。

AI 建议为 `COMPLETE` 时，Django 仍会检查置信度、知识哈希和全部必检项；校验通过后才将工单设为 `COMPLETED` 并按工单类型复位周期。

## 5. 异常报工

AI 建议为 `ABNORMAL` 且 Django 校验通过后进入 `ABNORMAL_REPORTED`：

```text
继续处理 → IN_PROGRESS → 重新点检和报工
或
创建关联修模任务 → REPAIR_LINKED → 修模完成 → IN_PROGRESS
```

异常工单不结单、不复位。

## 6. 比赛演示

1. 扫描并自动建单；
2. 选择候选人员；
3. 发送含点检知识和报工链接的邮件；
4. 点击链接上传说明和现场图片；
5. 展示 Django Webhook、平台拉取审核上下文与安全门禁；
6. 多模态能力未验证时展示 `NEEDS_MORE_INFO` 且工单未被误完成；
7. 多模态能力通过验证后，展示 Django 最终完成、周期复位或异常关联修模。
