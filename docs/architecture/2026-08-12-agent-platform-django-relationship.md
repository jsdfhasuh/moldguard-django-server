# 智能体平台与 Django 测试服务器关系说明

- **版本**：V2.0
- **日期**：2026-08-13
- **适用项目**：MoldGuard 模具保养智能预警与管理智能体
- **服务器定位**：无鉴权、无角色的比赛测试服务器
- **实施计划**：`docs/plans/2026-08-12-moldguard-django-implementation-plan.md`

---

## 1. 一句话说明

> **智能体平台负责对话、知识和邮件；Django测试服务器负责模拟数据、规则计算和业务状态。**

两者共同完成：

```text
预警
→ 工单
→ 选择人员并派工
→ 知识随单邮件
→ 开工/暂停/报完工
→ 点检与验收
→ 周期复位
→ 统计分析
```

本版本不设置主管角色，不进行用户登录、API Key 或权限鉴权。

---

## 2. 总体架构

```text
┌────────────────────────────────────────────┐
│              比赛智能体平台                │
│ 对话 │ Workflow │ 知识库 │ LLM │ 邮件     │
└───────────────────┬────────────────────────┘
                    │ HTTP + JSON
                    │ Request-ID
                    │ Idempotency-Key（建议）
                    ▼
┌────────────────────────────────────────────┐
│        MoldGuard Django Test Server        │
│ 模具 │ 周期 │ 提醒 │ 工单 │ 人员 │ 点检   │
│ 派工 │ 验收 │ 复位 │ 履历 │ 统计 │ 日志   │
└───────────────────┬────────────────────────┘
                    ▼
                  SQLite
```

---

## 3. 智能体平台负责

- 接收用户自然语言；
- 选择并调用 Django API；
- 执行每日巡检或手动巡检；
- 从知识库检索保养项目、点检、安全和验收要求；
- 用 LLM 生成预警、任务、催办和分析说明；
- 展示 Django 返回的候选人员；
- 由平台操作人员选择人员；
- 生成并发送邮件；
- 将知识快照和邮件结果回写 Django；
- 展示工单状态和统计结果。

平台可以显示“确认”“派工”“验收”等按钮或对话节点，但这些只是业务动作入口，不代表存在 Django 主管角色。

---

## 4. Django测试服务器负责

- 保存模拟模具数据；
- 根据开发吨位选择 30,000 或 50,000 模次规则；
- 保存和计算保养周期；
- 生成模次到期提醒；
- 为注塑模具生成每2个月信息提醒；
- 创建和查询工单；
- 返回候选人员；
- 保存平台选择的派工人员；
- 保存开工、暂停、恢复和报完工状态；
- 保存逐项点检结果；
- 保存验收、退回和转修模结果；
- 保存知识快照和邮件发送结果；
- 在保养、修模、换镶件或有效历史记录后复位周期；
- 输出工时、完成率和超时统计。

Django只校验业务状态和数据完整性，不校验调用者身份或角色。

## 5. 不再实现的内容

```text
主管角色
用户账号
人员登录
角色权限矩阵
X-API-Key
JWT / Token
OAuth
actor_role校验
生产级安全配置
PostgreSQL
Redis / Celery
SMTP
独立前端
```

Django Admin不是比赛主链路；演示数据主要通过种子文件和管理命令维护。

## 6. 仍保留的非安全能力

虽然没有鉴权，以下能力必须保留：

- 工单状态机；
- 数据库事务；
- 唯一约束；
- 重复工单检查；
- 幂等键；
- 请求ID；
- 错误码；
- 周期复位审计；
- 工单时间线。

这些能力用于保证流程一致，而不是识别用户身份。

## 7. 数据权威边界

| 内容 | 权威来源 |
|---|---|
| 模具、吨位、模次、位置 | Django测试数据 |
| 当前触发阈值 | Django |
| 周期基线和复位 | Django |
| 工单和派工状态 | Django |
| 点检执行结果 | Django |
| 知识正文 | 智能体平台知识库 |
| 邮件正文和发送动作 | 智能体平台 |
| 邮件发送结果记录 | Django，由平台回写 |
| 自然语言报告 | 智能体平台 |

平台不得自行修改模次、阈值、工单状态或周期基线。

## 8. 已确认规则

### 自动保养提醒

```text
开发吨位 <1000T  → 每50,000模次
开发吨位 >=1000T → 每30,000模次
```

钣金和注塑当前不区分一级、二级、三级保养。

### 每2个月提醒

```text
仅注塑模具
从cycle_baseline_time起每2个自然月
只提醒，不自动创建工单和派工
```

### 周期复位

```text
保养完成
修模完成
换镶件完成
有效历史记录导入
```

## 9. 核心交互时序

## 9.1 巡检

```text
平台 POST /alerts/scan
→ Django计算模次到期和时间提醒
→ 平台生成说明
```

## 9.2 工单与派工

```text
平台 POST /work-orders
→ Django创建待派工工单
→ 平台 GET /work-orders/{id}/candidates
→ 平台操作人员选择候选人
→ 平台 POST /work-orders/{id}/assign
→ Django保存派工
```

没有主管权限检查。

## 9.3 知识和邮件

```text
平台 GET /work-orders/{id}/knowledge-context
→ 平台检索知识
→ POST /knowledge-snapshot
→ 平台发送邮件
→ POST /notifications
```

## 9.4 执行和点检

```text
POST /start
POST /pause
POST /resume
POST /inspection-results
POST /report-complete
```

Django检查状态和必填内容。

## 9.5 验收和转修模

```text
平台操作人员选择：
accept / reject / transfer-to-repair
→ Django保存结果
```

没有主管角色，验收动作由演示流程直接触发。

## 9.6 周期复位

```text
保养验收通过
或修模完成
或换镶件完成
或历史记录导入
→ Django创建CycleResetEvent
→ 更新周期基线
→ 重算下一到期点和2个月提醒
```

## 10. 请求约定

不需要：

```http
X-API-Key
Authorization
```

建议保留：

```http
Content-Type: application/json
X-Request-ID: <optional>
Idempotency-Key: <recommended-for-write-actions>
```

可选操作人字段：

```json
{
  "operator_id": "TEST-OPERATOR-01",
  "operator_name": "比赛演示操作员"
}
```

仅用于日志。

---

## 11. 失败处理

- Django返回错误时，平台不得生成“操作成功”；
- 重复创建工单时返回现有工单；
- 邮件失败不回滚派工；
- 知识库无召回时不发送正式点检邮件；
- 非法状态跳转返回 `INVALID_STATE_TRANSITION`；
- 平台重试使用相同幂等键；
- 无效历史记录不得复位周期。

---

## 12. 测试服务器边界

由于没有鉴权：

- 只允许模拟数据；
- 人员姓名和邮箱必须是测试数据；
- 不接真实MES、ERP和生产数据库；
- 不长期保存真实业务数据；
- 比赛结束后停止服务；
- 企业落地时必须重新引入认证和权限。

---

## 13. 答辩表述

> 本项目中的Django只是一台比赛测试服务器，不接真实生产系统，因此没有建设复杂账号、主管角色和API鉴权。智能体平台负责对话、知识检索和邮件；Django保存模拟模具数据、工单状态、点检结果和周期复位。平台的每一步业务操作都通过Django接口写入，保证演示流程前后一致。幂等、事务和状态机仍然保留，用于防止重复工单和错误状态，而不是用于用户权限管理。

---

## 14. 最终总结

```text
智能体平台 = 对话 + 编排 + 知识 + LLM + 邮件
Django测试服务器 = 模拟数据 + 规则 + 工单 + 状态 + 点检 + 统计
```

没有主管角色，没有安全鉴权，但保留完整的测试业务闭环。
