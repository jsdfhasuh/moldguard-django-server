## 2. 已确认事项

### D02｜钣金与注塑自动保养触发规则

状态：`INTERNAL_CONFIRMED`

当前实际业务对钣金和注塑模具不区分一级、二级、三级保养。自动提醒统一按照模具开发吨位执行：

| 开发吨位 | 周期阈值 |
|---:|---:|
| `<1000T` | 每累计生产50,000模次 |
| `>=1000T` | 每累计生产30,000模次 |

自动计算：

```text
cycle_count = current_count - cycle_baseline_count
```

开发吨位为空时不得猜测，返回：

```text
DEVELOPMENT_TONNAGE_NOT_CONFIGURED
```

确认记录：

- [`2026-08-13-maintenance-trigger-rule-confirmation.md`](2026-08-13-maintenance-trigger-rule-confirmation.md)
- [`../plans/2026-08-13-moldguard-django-v3.2-trigger-rule-amendment.md`](../plans/2026-08-13-moldguard-django-v3.2-trigger-rule-amendment.md)

### D03｜每2个月提醒

状态：`INTERNAL_CONFIRMED`

当前按原业务语境适用于注塑模具：

```text
cycle_baseline_time + 2 calendar months
→ 生成提醒记录
→ 智能体平台发送提醒
→ 不自动创建保养计划
→ 不自动创建工单
→ 不自动派工
```

提醒必须明确：

```text
仅表示已满2个月，不代表模次保养条件已达到。
```

当前未把该时间提醒扩大到钣金模具。

### D04｜当前是否区分保养等级

状态：`INTERNAL_CONFIRMED`

当前实际业务不区分一级、二级、三级保养。

系统统一使用：

```text
maintenance_scope = PERIODIC_MAINTENANCE
maintenance_level = NOT_APPLICABLE
```

### D05｜历史一保、二保、三保资料的用途

状态：`INTERNAL_CONFIRMED`

以下资料不参与当前自动提醒、自动计划和自动派单：

```text
精密、普通、小型模具的3万、5万、10万模次
一保、二保、三保相关模次

外部A/B/C参考
```

限定用途：

```text

```

### D06｜钣金边板阈值与LC109冲突

状态：`RESOLVED_FOR_AUTOMATION`

该冲突不再影响当前自动触发，因为钣金和注塑均按开发吨位规则执行。边板类、LC109和历史分类阈值保留为知识库冲突，不得覆盖当前正式吨位规则。

### D08｜保养周期复位事件

状态：`INTERNAL_CONFIRMED`

以下事件均允许复位保养周期：

```text
保养完成
修模完成
换镶件完成
有效历史记录导入
```

复位更新：

```text
cycle_baseline_count
cycle_baseline_time
cycle_version
last_reset_type
last_reset_event_id
```

生效要求：

- 保养完成：全部适用点检完成，主管验收通过并生成履历；
- 修模完成：修模完成且经授权人员确认；
- 换镶件完成：事件状态达到 `COMPLETED_CONFIRMED`；
- 历史记录导入：通过字段、模具归属、发生时间、发生模次和权限校验。

历史记录使用实际业务发生时间和模次，不使用上传时间；旧于当前基线的记录默认只归档，不自动倒退当前周期。

确认记录：

- 两条开发吨位规则为 `INTERNAL_CONFIRMED`，可以驱动自动预警和后续计划流程；
- 知识库中的 `INTERNAL_SOURCE`、`PENDING_CONFIRMATION`、`EXTERNAL_REFERENCE` 不得自动驱动业务；
- 历史阈值不得覆盖当前吨位规则。

**建议：B，但每条规则必须独立白名单，且不得伪装为企业正式制度。**
