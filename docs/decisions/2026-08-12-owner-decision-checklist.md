## 1. 已确认业务边界

- 最新知识库是业务规则冲突时的最终解释；
- 无主管角色、无登录、无 API 鉴权；
- 不实现历史文件导入；
- 注塑、钣金触发规则按知识库第一部分；
- 注塑2个月条件自动建立时间周期工单；
- 正常报工直接完成，不增加验收角色；
- 异常报工继续处理或关联修模；
- 派工邮件包含一份点检知识和 Django 生成的报工链接；
- 字段统一使用知识库 V1.2 命名；
- 从 `main` 干净创建 `agent/competition-server-v1`，不复用测试分支代码和迁移。

## 2. 已确认实现决策

- 模型口径：6个业务模型 + `ClientRequestRecord` 技术模型；
- 同一周期模次与时间同时命中时合并为一张正式工单，模次规则为主规则；
- 正常报工允许 `ASSIGNED` 直接进入 `COMPLETED`；
- 无鉴权页面不输入员工编号，服务器使用工单 `assignee`；
- `current_load` 为固定 DEMO 值，不自动增减；
- `standard_hours` 和 `required_finish_at` 仅来自显式 DEMO 配置，缺失时返回 null；
- 邮件发送成功后锁定知识包，并保存规范化 JSON 的 SHA-256；
- HTML 与 JSON 报工共用同一服务和幂等机制；
- 一天版本优先后端 P0，再实现 HTML、关联修模、tracking 和部署；
- 不实现通用取消接口，避免增加非核心状态分支；
- 增加最小 `tracking/scan` 与 `work-orders/overdue` 以支撑过程追踪展示。
