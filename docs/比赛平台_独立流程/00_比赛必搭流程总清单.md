## 推荐实际搭建顺序

1. 确认 `GET /api/v1/health` 和 `GET /api/v1/meta` 正常。
2. 为流程 01 依次粘贴、验证并保存四个 MoldGuard 单输出节点；请求/响应信封显示为 V3，知识快照信封显示为 V4，单输入 HTTP 显示为 V2。知识快照 V4 新建注册，不覆盖原 V2/V3。
3. 搭流程 00，保存返回的 `run_id`；本流程不得换成自定义适配器。
4. 在平台创建并选择知识库 `模具保养知识库`。
5. 按 V2 文档新建流程 01，验证扫描自动建单、派工、知识检索、提示词约束的大模型严格 JSON、知识回写、Django 发信和任务卡预览。
6. 把流程 02 的 Webhook endpoint 配置到 Django 的 `MOLDGUARD_REPORT_REVIEW_WEBHOOK_URL`。
7. 需要先排除网络问题时，搭临时 Webhook 往返测试并验证 `roundtrip_status=COMPLETED`。
8. 只为流程 02 注册 `MoldGuard 豆包多模态 V1`，再按文档搭建 22 节点原生 HTTP 版；首次联调保持节点 10 的安全门禁。
9. 员工通过邮件中的 Django 链接提交文字和至少两张现场图片，验证平台被唤醒并能拉取完整审核上下文。
10. 完成“只改变图片像素会改变豆包观察或结论”的实测后，才开启 `COMPLETE` / `ABNORMAL` 回写门禁。
11. 搭流程 04 的两节点观察版，确认定时器真实 Data 后再扩成五节点心跳版。

## 单输出自定义节点

| 节点 | 职责 | 禁止事项 |
|---|---|---|
| `MoldGuard 请求信封 V3` | 为流程 01 生成单个 `method/url/json_body/context` 请求信封 | 不发送 HTTP；不接收平台报工 |
| `MoldGuard 单输入 HTTP V2` | 执行请求信封并原样传递 `context` | 不执行派工、知识或邮件业务规则 |
| `MoldGuard 响应信封 V3` | 提取业务变量，生成带 `[MOLDGUARD_OK]` 或 `[MOLDGUARD_FAIL]` 的单一 Message | 不修改 Django 业务数据 |
| `MoldGuard 知识快照信封 V4` | 解开大模型 Message 运行包装，接收严格 JSON 中的 `title/content/source`，自动生成内部字段并转换为单个受控知识回写请求 | 不接受说明性自由文本；不让 AI 生成内部 ID；诊断不输出输入值 |
| `MoldGuard 豆包多模态 V1` | 使用外部提示词和批量图片调用平台原生豆包模型，输出中文 Message 和严格 JSON | 不内置审核规则；不直接写 Django |

流程 01/02 的业务分支由平台原生“如果-否则”节点执行。流程 02 的 GET/POST 全部使用原生 `JSON HTTP 请求`，只使用豆包多模态一个自定义节点；流程 00 继续使用平台原生 HTTP 节点。

## 报工权责口径

```text
员工在 Django 页面上传文字和图片
→ Django 保存 ReportSubmission(PENDING_REVIEW)
→ Django Webhook 唤醒流程 02
→ 平台 GET 审核上下文和图片
→ 平台给出 COMPLETE / ABNORMAL / NEEDS_MORE_INFO 建议
→ Django 校验并最终裁决
```

- 平台不得直接写工单状态、周期、履历或告警。
- Webhook 成功只证明平台已被唤醒，不证明报工通过。
- 自定义豆包节点已构造真实图片内容块；像素对照测试通过前，流程 02 节点 10 只放行 `NEEDS_MORE_INFO`，其余情况走固定安全模板。
- `COMPLETE` 或 `ABNORMAL` 必须等多模态能力通过真实图片测试后才能启用。
- Django 是完工、异常、周期复位和履历的唯一权威。

## 流程 01 后端前置条件

1. `POST /api/v1/alerts/scan` 命中时同时创建或复用工单，并返回 `work_order_id`。
2. `POST /api/v1/work-orders/{work_order_id}/auto-assign` 返回扁平字段 `assignee_id`。
3. `GET /api/v1/work-orders/{work_order_id}/knowledge-context` 只返回平台检索上下文。
4. 平台调用 `POST /api/v1/work-orders/{work_order_id}/knowledge` 回写实际检索知识包。
5. `POST /api/v1/work-orders/{work_order_id}/send-email` 只接收 `client_request_id`。
6. 发信成功必须返回 `new_email_status=SENT` 和非空 `email_message_id`。

## 能力口径

- 平台大模型任务卡是展示结果，不是邮件发送证明。
- 邮件发送成功只认 Django 的 `new_email_status=SENT` 和真实 `email_message_id`。
- P04 只证明数组原样传递，不证明 `循环` 能展开 HTTP 嵌套数组。
- 平台无法读取报工图片时，P10/P11 不得标记为完成审核能力。
